# 项目档案

档案是这本书在对话外面的记忆。换对话、换智能体，只要读档案就能接着写。

## 档案里有什么

```text
书名/
├─ 00-写作规则.md        怎么写、写完怎么改、怎么记（每次都读）
├─ 01-项目状态.md        写到哪、下一步做什么、哪个版本有效、交接（每次先读）
├─ 02-设定.md            世界规则、能力和限制、重要地点和物品
├─ 03-人物.md            每个人物不太会变的东西
├─ 04-大纲.md            故事框架、分卷纲、滚动细纲
├─ 05-开书记录.md        作者的偏好、原始脑洞和脑洞体检、作者否掉的、读者分析、选定的方案、开书自检结论
├─ 记录-人物现状.md      每个人物现在的位置、身体、知情、持有、关系
├─ 记录-伏笔.md          没收的伏笔和读者在等的事
├─ 记录-时间线.md        每章一两句，只记会影响后面的事
├─ 记录-废弃设定.md      作者推翻的旧设定，防止被写回来
├─ 正文/                 作者采用的正式正文，每章一个文件
└─ 待确认/               还没被采用的处境卡、初稿和候选
```

另外三个文件夹用到时才建：`待确认/已处理/` 放采用后留档的处境卡、初稿和旧候选；`审读/` 放冷读报告；`记录-归档/` 放每一卷写完时的卷总结和挪过去的旧记录（见 `references/卷末和完本.md`）。

这本书里钱、物品、身份、权限要按数量算的（比如修仙的灵石、种田的存粮、系统的积分），再加一份 `记录-资源.md`。建档时题材还没定，先不建；开书 4.1 搭完世界，看得出有没有要算数的东西时问作者一句，要就补建。

文件名沿用原版 4.0，但格式更严格（条目格式见下，项目状态多了“交接”一节，进度字段归工具管），原版建的项目不能直接用。

## 建档步骤

1. 问作者项目放在哪个文件夹。没给就问，不要猜路径。
2. 目标文件夹不是空的：先只读看一遍里面有什么，告诉作者，不要删、不要覆盖、不要搬动已有文件。里面有作者以前的小说材料的，建好档案以后按开书的步骤整理进来。
3. 运行 `python3 references/tools/novel.py init <项目文件夹>`。它把 `references/写作规则-默认版.md` 复制成 `00-写作规则.md`，把 `references/templates/` 里除 `记录-资源.md` 以外的文件复制过去，建好 `正文/` 和 `待确认/`，已有的同名文件一律不动并列出来。没有 Python 就手做这几件事。
4. 作者已经给了材料（设定、人物、大纲、写好的章节）的，拆开填进对应文件。只整理作者给的东西，不新加设定，不替作者补剧情；没有的写“待定”。大纲和已写正文对不上的，单独列出来问作者。
5. 作者已经有写好的正文的，按正文实际写到的内容填三份记录。只记正文里确实发生的事；大纲里还没写到的不能记成已经发生。
6. 告诉作者：建了哪些文件，每份里大概有什么，还有哪些等他定。

## 每份文件管什么、不管什么

同一件事只在一个地方记当前值，不然两处一改一不改，AI 就不知道该信哪个。

- **00-写作规则.md** 只写怎么写，不写这本书的设定和剧情。作者认可了某次改法，经作者同意后合并进来（见 `references/改稿.md`）。
- **01-项目状态.md** 只记进度、版本、下一步和交接，不复制规则和设定。“交接”记作者在对话里说过、影响后面、但还没写进设定、规则或大纲的话，以及上次停在哪、当前张力；写进正式文件以后从交接里删掉。“当前唯一候选”只能有一个，不能把两个文件都叫最终版。“定稿参照章”记作者点过头、用来定腔调的那一章。已采用到、候选指针、最近一次回写和回写后的下一步由 `novel.py adopt` 和 `novel.py done` 改，你不手改；`novel.py check` 会比对它们和实际文件。
- **02-设定.md** 记已确认的世界规则。已确认但正文还没揭示的，注明“尚未揭示”；没确认的候选单独放在“待定”里。一次事件不能自己总结成通用规则：比如“第三章主角救人后倒计时变成七天”是一次经历，记进时间线；原因是什么、是不是每次都这样，没确认之前不写成设定。
- **03-人物.md** 记身份、性格、说话的样子、想要什么、怕失去什么、在不同的人面前表达有什么不同。位置、伤势、当前知道什么，不在这里记，在人物现状里。
- **04-大纲.md** 记故事框架（全书故事和阶段）、作者确认的卖点、各卷分卷纲、当前这一批细纲。已经写成正文的细纲可以挪到文末“已写”部分，不删。
- **记录-人物现状.md** 写到最新采用的一章为止。人物“知道的事”和“误以为的事”分开记。作者知道不等于人物知道，怀疑不等于证实。
- **记录-伏笔.md** 没收的写在前面，注明埋在第几章、预计什么时候、什么条件下收；收掉的挪到最后，注明第几章收的。没收的伏笔不管多久以前埋的，都要留在能查到的地方。
- **记录-时间线.md** 每章一两句，只记会影响后面的事。一卷写完，这一卷的时间线整段挪进卷总结。
- **记录-废弃设定.md** 记作者推翻的设定：原来是什么、为什么废、被什么替代、作者哪次定的。
- **记录-资源.md**（需要时才有）记核对过的当前数量，以及最近一次变化来自哪一章。

这些记录是已采用正文的摘要。记录和正文对不上时，回去查正文，以正文为准，不能让摘要反过来改正文。

## 条目格式：让工具找得到

`novel.py brief` 按名字找条目，靠下面几条约定。`novel.py check` 会把格式不对的地方当错误报出来，建档和回写时就按这个写：

- **人物、地点、物品、组织各一节。** `03-人物.md` 和 `记录-人物现状.md` 里每人一节 `## 名字`；`02-设定.md` 的“重要地点和物品”下每样一节 `### 名字`。标题用正文里最常用的叫法，两份人物文件里同一个人的标题要一样。
- **标题下第一行写别名。** `- 别名：师姐、林师姐`，外号、称呼、职位叫法都写上，顿号隔开；没有就写“无”。只有一个字的名字和别名，工具扫不出来，尽量写成两个字以上的叫法。
- **人物现状写状态。** `- 状态：在场`（在场／离场／死亡／失踪）。check 会提醒死亡、失踪的人出现在细纲里。
- **伏笔写涉及谁。** `### F001` 下写 `- 涉及：林晚、九转丹方`，用的是上面那些标题。伏笔编号全书不重复。
- **细纲每章两行索引。** `### 第38章：章名` 下第一行 `- 出场：……`，第二行 `- 伏笔：F001、F004`（没有就写“无”）。死亡、失踪的人物有意出现时，加 `- 特殊出场：赵三（回忆）`。
- **出场的都要有条目。** 细纲“出场”里列的名字，最晚在这一章回写时建好条目；`novel.py done` 查到没有会拦住。

## 每份文件多长

“只读需要的”撑不撑得住，看档案会不会无限长。下面是软上限，`novel.py check` 超了会提醒：

| 文件 | 上限（字） | 超了怎么办 |
|---|---|---|
| 01-项目状态.md | 6000 | 做完的事不留历史；交接一节不超过 2000 |
| 00-写作规则.md | 20000 | 请作者一起把“本书的其他要求”里重复、过时的合并删掉 |
| 记录-人物现状.md | 20000 | 卷末把离场超过一卷的人物整段挪进卷总结，原处留一行“见第N卷总结” |
| 记录-伏笔.md | 15000 | 已收的挪进卷总结，只留编号和第几章收的 |
| 记录-时间线.md | 8000 | 一卷写完整段挪进卷总结（超过 60 章也会提醒） |
| 02-设定.md、03-人物.md | 30000 | 只留已确认的；不出场的次要人物合并成一节 |

挪走只是换地方，不删内容，挪完核对卷总结里找得到。
