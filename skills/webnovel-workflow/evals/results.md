# 实跑记录

## 2026-11-13 第三轮：借鉴 oss-mentor 以后的三个新场景

三本书（状态卡、已接受偏差、作者执笔），每本一个全新会话（Claude Opus 5.5，没有子智能体可用），只发 prompt，作者不回复。

| 场景 | 结果 | 要点 |
|---|---|---|
| status-card（问进度） | 通过 | 跑了 check 和 status，没动笔；状态卡给了章数字数、上次以来、三个问题按轻重排、三件要定的事各附推荐、回答后做什么；篇幅超过十行 |
| accepted-gap（已接受偏差） | 通过 | 字数、“本书的写法”、周管事三条都没再提；第4章写成约 480 字的短章；搭档模式下待确认事项只有一条 |
| author-writes（作者执笔） | 通过 | 没改作者稿、没给改写段落；审读找出受伤的手左右写反；作者没说采用就没登记 |

跑出来、已经修掉的问题：

- 细纲列了出场但没有条目的人物，平时 check 不提醒（只有 done 拦），和 SKILL.md 的说法对不上。check 现在对还没写的细纲给提醒。
- 已采用章节一直偏离每章目标字数，status 不报。status 现在自动拿项目状态里的目标对比。
- “每章三四百字就行”这类其实是新目标的偏差，和旧目标并存，让会话不知道按哪个数。现在规定直接改设置、记进最近的决定。
- 状态卡“十行以内”装不下三件事加推荐，改成一屏以内、每项一两句。
- 作者执笔时审读结果就是交付物，和“作者没问就不附分析”冲突；自查时先只读正文再对照细纲；细纲剩不到三章是提醒不是拦；照正文更正只改事实不改措辞，告诉作者的那句放在消息末尾、不占待确认事项；作者自己在交接里的指示和细纲冲突时照交接写、不再问；开书进度和文件对不上以文件为准。都已写进 SKILL.md 和 写一章.md。

## 2026-11-13 第二轮：修完第一轮的问题后重跑

六本书（新加“作者采用”“状态漂移”），每本一个全新会话（Claude Opus 5.5，没有子智能体可用），只发 prompt，作者不回复。

| 场景 | 结果 | 要点 |
|---|---|---|
| resume-handover（续写） | 通过 | brief 报出执事没条目，按第3章正文补上再写；候选守住交接和设定，没泄露“尚未揭示”；自检如实标成自查 |
| resume-interrupted-writeback（回写中断） | 通过 | 按 check 的已改／未改清单补完，铜钱停在 8；给执事建了条目，done 才放行 |
| resume-dead-character（死人出场） | 通过 | check 直接报错，没备资料、没写初稿就停下问作者 |
| resume-mid-interview（访谈中断） | 通过 | 先记问题再问，只问缺的两样 |
| resume-adopt（作者采用） | 通过 | 用 adopt 采用，补执事条目，铜钱 10→8，done 放行；回写完停下问要不要接着写 |
| resume-status-drift（状态漂移） | 通过 | check 报错后停下问作者，没自己补登记，没写第5章 |

跑出来、已经修掉的问题：

- 作者放进 `正文/` 的章节没有补登记的路。adopt 现在接受 `adopt N 正文/第NNN章.md`，在已采用到是 N-1 时只开回写、不动正文。
- “记录跟上正文”的更正只写在回写一节，开工时发现能不能改不清楚；作者后来的话和他更早确认的细纲冲突时听谁的；确认过的细纲和正文矛盾怎么办；check 有错误时要不要备资料；作者只说“采用”时回写完停不停；细纲定的结果正文没写到怎么记；自查结果存哪；done 之后“下一步”谁改；交接的“更新于”停在半路怎么写；开书阶段读不读开书记录。都已在 SKILL.md（新加“以谁为准”一段）、写一章.md 和项目状态模板里写清。
- 上一章整章都比 1500 字短时，资料包标签写的是“最后约 N 字”。现在标成“全文”。

还没测到的：独立读者那一步（测试会话开不了子智能体）；状态漂移里作者确认后的补登记（要第二轮对话）。

示例书的毛病：`build_fixtures.py` 在前三章走完采用流程以后才写入记录，所以第3章的快照看起来“只改了时间线”，几个会话都注意到了。这是造书的偷懒，不是技能的问题。

## 2026-11-13 第一轮

用 `build_fixtures.py` 造的四本书，每本开一个全新会话（Claude Opus 5.5，没有子智能体可用），只发 prompt，作者不回复。

| 场景 | 结果 | 要点 |
|---|---|---|
| resume-handover（续写） | 通过 | 跑了 check 和 brief；第4章候选里林晚没揭穿顾长风，没写黑化，没写回 D001 的血缘，“尚未揭示”没泄露；自检如实标成自查 |
| resume-interrupted-writeback（回写中断） | 通过 | 从 check 的已改／未改清单接着补，铜钱停在 8 没再减；done 放行前没动第5章 |
| resume-dead-character（死人出场） | 通过 | 动笔前停下，给作者三个改法附推荐 |
| resume-mid-interview（访谈中断） | 通过 | 没重问前四轮，只问缺的两样，问完存盘再停 |

跑出来、已经修掉的问题：

- 下一章细纲里出现死亡人物，check 只给提醒，只读 SKILL.md 会照写。改成错误，有意的用“特殊出场”一行放行。
- 第3章新出场的执事一直没建条目，check 和 done 都没拦。done 现在要求这一章细纲“出场”里的名字都有条目。
- 候选指针“归工具管”和“你来登记”说法打架；细纲替人物假定了正文没写过的事、缺主线背景材料、参照章和目标字数打架、发现旧记录和正文不符时怎么办，都没写。已在 SKILL.md 和 写一章.md 里写清。
- 访谈中途的问题什么时候记、力量体系模块什么时候读、开书阶段交接的“更新于”怎么写，已写清。

示例书本身的毛病（前三章只有约 300 字、开书记录是空的、第3章回写只改了时间线）是造书时偷的懒，不是技能的问题，几个会话都把它们当成待确认事项报了出来。
